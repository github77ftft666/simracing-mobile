# ТЗ — PitLink PWA и локальный ПК‑ресивер

## Цель

PitLink заменяет клавиатуру в PC‑гоночных играх смартфоном. Пользователь держит телефон горизонтально: наклон влево/вправо управляет рулём, наклон от себя — газом, к себе — тормозом. Приложение не транслирует игру и не отправляет игровые данные в интернет.

## Платформы и границы первой версии

- Клиент: PWA для Android и iPhone, установка из браузера; для iOS позже выпускается нативная оболочка в App Store.
- ПК: Windows 10/11, отдельный локальный ресивер.
- Поддерживаемый транспорт: WebSocket через одну Wi‑Fi/LAN сеть или USB‑tethering. «По проводу» означает сетевое USB‑подключение: браузер iPhone не получает прямой доступ к USB HID ПК.
- Не входит в MVP: консольные PS/Xbox, force feedback, облачный relay, учётные записи, телеметрия игры.

## Управление

| Функция | Ввод | Выход |
| --- | --- | --- |
| Руль | поперечный наклон / `beta`, dead zone 5°, полная шкала 32° | аналоговая ось −1…1 |
| Газ | продольный наклон / `gamma` вправо | аналоговая ось 0…1 |
| Тормоз | продольный наклон / `gamma` влево | аналоговая ось 0…1 |
| Сцепление | вертикальная сенсорная шкала в МКПП | аналоговая ось 0…1 |
| КПП | правая половина: верх «+», низ «−» | дискретное событие |
| МКПП | H‑сетка 1–6 + N | выбранная передача |

Кнопка «Центр» сохраняет текущую ориентацию телефона как нейтральную и на первом касании запрашивает motion‑permission, необходимое на iOS. Для руля действует безопасная зона ±5°, для педалей — ±7°: внутри неё все управляющие оси равны нулю.

## Подключение и порты

| Назначение | Протокол | Порт | Правило |
| --- | --- | ---:| --- |
| Поток управления | WSS | 32100/TCP | ресивер слушает только локальный интерфейс/LAN; Windows Firewall — Private network |
| Будущее обнаружение ПК | UDP broadcast | 32101/UDP | не реализовано в PWA MVP: iOS‑браузер не поддерживает UDP |
| QR‑страница | HTTP | 32102/TCP | открывается локально на ПК и показывает QR сопряжения |
| Настройка CA | HTTP | 32103/TCP | отдаёт только локальный корневой сертификат и iOS‑профиль |

Windows Controller создаёт и хранит локальный корневой CA, сертификат WSS с SAN текущего LAN‑IP и секрет сопряжения в `%LOCALAPPDATA%\PitLinkController`. QR несёт `wss://IP-ПК:32100`, секрет сопряжения и страницу настройки CA. Перед первым подключением пользователь устанавливает CA: на iPhone — профиль и затем включает полное доверие в «Доверии сертификатам», на Android — как CA‑сертификат в настройках безопасности. При смене LAN‑IP контроллер выпускает новый серверный сертификат, но CA остаётся тем же. При USB‑tethering используется IP, выданный адаптеру USB‑модема. Канал не должен иметь внешний DNS, relay или облачное API.

При запуске упакованный Windows Controller запрашивает через UAC правило Windows Firewall только для Private network и TCP 32100/32102/32103. PWA автоматически переподключается после уже успешного сопряжения. iOS требует явного пользовательского нажатия для запроса датчиков и камеры — кнопка «Начать / подключить ПК» объединяет запрос motion‑permission и подключение; сканирование QR запрашивает камеру.

## Протокол

Клиент отправляет `state` раз в 16 мс:

```json
{"type":"state","seq":42,"steering":-0.3,"throttle":0.7,"brake":0,"clutch":0,"handbrake":false,"manualGear":3}
```

Одноразовые события: `{"type":"event","action":"gearUp"}`, `gearDown`, `center`. Ресивер обязан отвергать некорректный JSON, использовать последний валидный state и при разрыве соединения немедленно сбрасывать все оси в ноль.

## Архитектура

- `src/` — офлайн‑PWA UI, sensor fusion, локальная настройка endpoint в `localStorage`.
- `receiver/` — Node.js WebSocket‑ресивер на `32100`.
- Следующий модуль для Windows: Rust/C# adapter с ViGEm/XInput. Он принимает нормализованные оси и кнопки из ресивера; PWA не эмулирует HID напрямую.

## Windows Controller и Automobilista 2

- Исходники Windows‑ресивера находятся в `controller-desktop/`; сборка создаёт `PitLink-Controller.exe`.
- Приложение один раз создаёт pairing‑token и хранит его локально вместе с ключами Controller, поэтому сопряжённый телефон переподключается после перезапуска Controller. QR‑код позволяет подключить новый телефон или восстановить пару; Controller запускает WSS на 32100, QR‑страницу на 32102 и локальную страницу установки CA на 32103.
- Профиль Automobilista 2 переводит аналоговые команды телефона в клавиатурные: `A/D` — руль, `W` — газ, `S` — тормоз, `Space` — передача вверх, `Left Alt` — передача вниз. В AMS2 нужно выбрать схему Keyboard и назначить эти клавиши в Options → Controls.
- Такой профиль — цифровой fallback. Полноценные аналоговые оси потребуют следующего слоя виртуального XInput‑геймпада/драйвера.
- QR несёт локальный `wss://` endpoint и адрес установки CA. PWA не пытается обойти проверку сертификата: она предлагает сначала установить CA, затем подключиться.

## Безопасность и приватность

- Нет аккаунтов, аналитики, рекламы, облачной базы или передачи игрового экрана.
- Разрешение motion запрашивается только по действию пользователя.
- Endpoint требует секрет сопряжения, показанный ресивером; MVP рассчитан на доверенную домашнюю LAN.
- В production включить Origin allowlist, ограничение одного активного контроллера и аварийный timeout 150 мс.

## Критерии приёмки MVP

1. PWA ставится на Android и iOS и блокирует управление в portrait.
2. После выдачи motion permission руль, газ и тормоз плавно меняются от наклона.
3. Кнопка центрирования обнуляет органы управления.
4. После установки локального CA подключение к `wss://LAN-IP:32100` показывает статус и передаёт state с частотой около 60 Гц.
5. Плюс/минус и МКПП отправляют выбранные передачи; ресивер журналирует события.
6. При отключении сокета UI возвращается в офлайн‑статус.

## Запуск

```powershell
npm install
npm run dev
cd receiver
npm install
npm start
```

Откройте PWA с телефона по адресу Vite‑сервера в локальной сети. Для production соберите `npm run build` и отдавайте `dist` по HTTPS: iOS требует secure context для датчиков.
